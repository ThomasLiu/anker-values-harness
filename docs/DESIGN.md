# 设计取舍

这份文档记录「为什么这么做」，以及「哪些做法被否掉了」。

## 一、为什么不能只写 prompt

把价值观写进 system prompt 会失效，不是措辞问题，是结构问题：

| 失效原因 | 表现 |
|---|---|
| **不可判定** | 「求极致」没有通过/不通过，模型只能靠自我感觉。自我感觉的默认值是「我已经很努力了」 |
| **不显形** | 90% 的任务里三条价值观并不冲突，模型感知不到需要调用，于是它变成背景噪声 |
| **无代价** | 违反了没有任何反馈。没有代价的规则，在优化压力下一定被丢掉 |

三者叠加的结果：价值观段落越长，越像免责声明。

**结论：价值观必须被编译成「不能通过的检查」，而不是「要努力的方向」。**

## 二、三层编译

```
values.toml  ──►  vh prompt  ──►  vh lint  ──►  vh report
  事实源           注入层          判定层        观测层
```

- **注入层**只注入当前阶段的规则。pre_task 4 条、pre_deliver 9 条、post_task 3 条——刻意不一次性灌全量，因为注意力是有限资源。
- **判定层**优先用确定性检查。能自动判的绝不交给模型判，每多一条确定性规则，就少一分「看起来在遵守」。
- **观测层**记录每次 lint 的结果。没有指标就没有价值观——`vh report` 里「最常被拦的规则」就是漂移信号。

## 三、为什么求极致排在仲裁最后

```
安全/不可逆  >  共成长(长期资产)  >  第一性(判断质量)  >  求极致(打磨程度)
```

三条价值观一定打架。只给规则不给仲裁，模型会自己选成本最低的那条，而且不告诉你。

把「求极致」放最后是**故意的**：它是最容易被时间挤掉的一条。必须让它在取舍中被**明确牺牲**，而不是被**悄悄遗忘**。

配合的唯一硬规则是「不允许静默降级」——任何取舍必须写成一行 `取舍声明：为了 X 放弃了 Y，因为 Z。牺牲可接受的前提是：……`。

实测数据支持这个设计：裸跑组 3/4 份产出存在静默降级（把「摸清客户用哪家」换成「猜供应商类型」、把「猎头团队」换成「甲方招聘团队」），加了 gate 之后同样的偷换仍然发生，但被写了出来。**偷换不可怕，偷换不说才可怕。**

## 四、被否掉的做法

**让主 agent 自评。** 自我一致性偏差会让它永远给自己高分。critic 必须是独立上下文、独立人格，且看不到主 agent 的自我辩护。见 `evaluator/critic.md`。

**每个任务都跑全量 rubric。** 会慢一个数量级，两周后一定被关掉。所以有 `--brief`：只注入 blocking 规则，给轻任务用。给每个任务都套全套 gate 的后果是 harness 被关掉——这是最常见的一种死法。

**把规则藏起来。** 试过，没用。规则透明时 agent 会照着写；规则不透明时 agent 会猜错然后返工。真正的问题不是透明，是规则太弱——所以方向是加强检查，不是加密配置。

**用「应该」「尽量」「优先考虑」。** 模型必然走成本最低路径。必须写成「必须 / 否则返工」。

## 五、为什么用 TOML 而不是 YAML

Python 3.11+ 自带 `tomllib`，零依赖。一个要装 PyYAML 才能跑的检查器，在 CI 里会先死在依赖上。

## 六、已知缺陷

**检查器只判结构，不判质量。** 一个足够刻意的 agent 能写出形式上合规、实质空洞的产出。这套东西防的是无意识的偷懒，不是防恶意。

实测里 agent 自己总结了三种「形式糊弄」：
- 红队自查写「指出弱点但不处理」，用自查豁免自己
- 关键假设的验证方式写成「让客户一句话推翻」，把验证成本转嫁给对方
- 技术债的「什么时候还」写成「客户给数据后重算」，等于无到期日

这些都是结构合规但实质空洞。**能兜住它们的只有 critic，而 critic 是概率性的，不是门禁。**

**正则会被绕。** 触发词表永远补不完。应对方式不是穷举，是给每次逃逸加一条回归用例（`bench/negative/`），让逃逸至少不会复现。

**样本量不够。** 实测 n=4，每场景一个 critic，critic 本身也是模型。数据能说明方向，不能说明幅度。

## 七、如果要继续做

1. **跑 `post_task`。** 第一轮实验全部停在交付，共成长这一维度实际上没被测到。
2. **验证 `fp.number-provenance`。** 新加的规则只知道能拦住，不知道会不会导致过度返工。
3. **把配置移出业务仓库。** 用 `VH_ROOT` 指向独立目录，agent 只能看到 `vh prompt` 的输出。
4. **critic 常态化。** 现在 critic 是手动的，应该变成交付前的一次固定调用，并且和 lint 结果一起进 telemetry。
