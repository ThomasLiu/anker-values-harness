# gate: 任务后（post_task）

> 规则的事实源是 [`values.toml`](../values.toml)。本文件只讲怎么做得更好。
>
> 生成阶段 prompt：`vh prompt post_task --task "……"`

## 这个 gate 在防什么

防的是**反思完什么都没变**。

大多数 agent（和人）的复盘是无效的，因为它产出的是感想，不是资产。感想无法被下一次任务加载，资产可以。

## 硬标准：沉淀必须是一个文件 diff

不是一段文字，是一个可被下次加载的东西。三种形态：

| 类型 | 落地位置 | 例子 |
|---|---|---|
| **checklist / SOP** | `quality/recall/72h-checklist.md` | 把召回启动的监管备案、物流仓、客服话术做成并行勾选表 |
| **规则** | `values.toml` 新增 rule | 「来料变更必须有对照测试」写成 `qc.cell-change-gate` |
| **memory** | `memory/YYYY-MM-DD.md` | 「A 供应商的检测报告只认第三方，自检报告不采信」 |

如果这次任务确实没有可复用的东西，也要写出来并说明为什么——但这种情况很少，通常只是没认真找。

## 决策记录

一行一个决策，含理由。三个月后没人记得为什么这么做，于是要么重复讨论，要么不敢改。

```
## 决策记录
- 决定全批次召回而非只召回 04 月后批次：03 月批次缺对照测试数据，「说不出低多少」在热失控上等于「不能说安全」
- 决定不等 60 颗电芯测试结果就公告：监管备案有窗口期，等不起；代价是可能发更正说明
```

## 重复踩坑检查

沉淀前先翻一遍 memory 和最近的 telemetry：

```bash
vh report
```

如果这次踩的坑在 `rule_fails` 里已经出现过，说明上次的沉淀没生效。这比新增一条资产更重要——**同一个坑踩两次，是 harness 的问题，不是运气问题**。

## 出口条件

```bash
vh lint post_task <沉淀记录>
```

exit 0 才算任务完成。
