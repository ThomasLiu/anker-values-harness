# gate: 任务后（post_task）

> 规则的事实源是 [`values.toml`](../values.toml)。本文件只讲怎么做得更好。
>
> 生成阶段 prompt：`vh prompt post_task --task "……"`

## 这个 gate 在防什么

防的是**反思完什么都没变**。

大多数 agent（和人）的复盘是无效的，因为它产出的是感想，不是资产。感想无法被下一次任务加载，资产可以。

## 硬标准：沉淀必须是一个文件 diff

不是一段文字，是一个可被下次加载的东西。三种形态：

| 类型 | 落地位置 | 例子 |
|---|---|---|
| **skill** | `skills/<domain>/<name>.md` | 把这次手工做的竞对扫描固化成 5 步 SOP |
| **规则** | `values.toml` 新增 rule | 「报价必须附测算」写成 `bd.price-anchor` |
| **memory** | `memory/YYYY-MM-DD.md` | 「A 客户 HR 只回微信不回邮件」 |

如果这次任务确实没有可复用的东西，也要写出来并说明为什么——但这种情况很少，通常只是没认真找。

## 决策记录

一行一个决策，含理由。三个月后没人记得为什么这么做，于是要么重复讨论，要么不敢改。

```
## 决策记录
- 报价定 22%：三档测算下毛利额最大，且客户池对 3 个点不敏感
- 放弃全量覆盖：时间不够，客户接受两轮
```

## 重复踩坑检查

沉淀前先翻一遍 memory 和最近的 telemetry：

```bash
vh report
```

如果这次踩的坑在 `rule_fails` 里已经出现过，说明上次的沉淀没生效。这比新增一条资产更重要——**同一个坑踩两次，是 harness 的问题，不是运气问题**。

## 出口条件

```bash
vh lint post_task <沉淀记录>
```

exit 0 才算任务完成。
