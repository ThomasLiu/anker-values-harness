# gate: 任务前（pre_task）

> 规则的事实源是 [`values.toml`](../values.toml)。本文件不重复规则定义，只讲**怎么做得比 lint 要求更好**。
>
> 生成阶段 prompt：`vh prompt pre_task --task "……"`

## 这个 gate 在防什么

防的是**用解法冒充问题**。

产品经理说「下个版本把深色地毯的定位问题修一下」，这是解法。真实问题可能是「下视传感器在低反射率表面到了物理极限」——如果直接去调参，调得再好也修不掉。

第一性在这里的具体含义：把需求拆到不能再拆，直到每一条都能被验证。

## 四个必答问题

**1. 表面需求是什么**
原话复述，不要加工。加工会丢掉信息。

**2. 我判断的真实目标是什么**
写你的判断和依据。判断错了没关系——写出来才能被纠正，藏在心里就永远是错的。

**3. 硬约束是什么**
时间、预算、合规、不可动的东西。区分「真约束」和「习惯」：真约束推翻不了，习惯可以。

**4. 关键假设是什么**
这是唯一会被 lint 强制检查的部分。标准是**可证伪**。

| 不合格的假设 | 为什么不行 | 合格的写法 |
|---|---|---|
| 用户应该能接受 78℃ 的外壳温度 | 「应该」不可证伪 | 满载持续时长不超过 20 分钟的工单占 92% → 验证：拉近 6 个月工单统计时长分布 |
| 二供报价更低 | 模糊，无法验证 | 二供报价 7.6 元、一供 8.2 元，但二供要预付 30% → 验证：拉现金流排期表算实际占用成本 |
| 这个批次的风险不高 | 没有判据 | 该批次投诉率 0.76‰，问题批次 6.1‰ → 验证：按 SN 交叉电芯批次重算 |

一条好假设长这样：

```
- 假设：热源主要是变压器和同步整流 MOS，不是外壳材料的导热系数
  → 验证：热像仪扫 45℃/满载/30 分钟稳态，看热点是否集中在变压器与 MOS 焊盘
```

## 验收标准的写法

标准必须在结果之前定。定晚了，标准会被结果倒推——这是人（和模型）的本能。

可判定的标准有三个特征：有数字、有二值判据、或者有明确的通过条件。

```
不合格：把温升问题解决好，保证按时交付
合格：  45℃/满载/30 分钟稳态下外壳 ≤75℃、绕组 ≤110℃，连续 3 次复测一致；
        结论必须回答「出货 / 不出货 / 有条件出货」三选一，并给出条件的具体数值门槛
```

## 分层：不是所有任务都要跑全量

轻任务（改个措辞、查个数）用 `vh prompt pre_task --brief`，只注入 blocking 规则。
重任务（对外交付、影响决策）跑全量。

给每个任务都套全套 gate 的后果是 harness 被关掉——这是最常见的一种死法。

## 出口条件

```bash
vh lint pre_task <你的拆解卡>
```

exit 0 才能进下一步。
