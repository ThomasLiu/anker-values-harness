# 5 人猎头团队轻量 ATS 选型与落地方案

**结论先行**：主选 **谷露 Gllue 猎头版**，5 个账号，年费 **1.2–2.0 万**，落在预算内。预算被砍或想先跑通流程，用 **飞书多维表格自建**，年费 0–3,000 元。两条路都能把「Excel + 微信」收敛成一个系统，区别只是花钱买成熟度，还是花时间省钱。

---

## 一、先把问题定义清楚

现在的乱，不是「没有系统」，是四件事没有唯一出口：

1. **候选人没有唯一身份**。同一个人在三张表里出现三次，手机号一个带 +86 一个不带，查重靠人眼。
2. **沟通记录只活在微信里**。换手机、清缓存、同事离职，聊到哪一步就断了。Excel 里只有「已推荐」，没有「为什么没成」。
3. **流程状态靠人脑**。谁该跟进、卡在客户反馈还是候选人犹豫，只有当事人知道。5 个人还能靠喊，有人休假就断档。
4. **归属说不清**。谁先接触、谁推进，月底对账靠翻聊天记录——这是团队里最伤感情的地方。

所以选型的第一标准不是功能多，是**5 个人每天真的愿意往里填**。填不进去的 ATS，三个月后一定退回 Excel。

---

## 二、选型标准（按权重排序）

| 权重 | 标准 | 说明 |
|---|---|---|
| ★★★★★ | 简历一键入库 + 自动解析 | 微信/邮箱收到的 PDF、Word 拖进去就出结构化字段，否则没人录 |
| ★★★★★ | 手机号/邮箱自动查重 | 抢单和重复录入的唯一技术解法 |
| ★★★★☆ | 候选人—职位双向关联 | 猎头不是 HR，核心是「这个人推过哪些职位、结果如何」 |
| ★★★★☆ | 跟进提醒 + 超时预警 | 替代「靠记性」，5 人团队最高频的失效点 |
| ★★★☆☆ | 归属规则可配置 | 首录归属、保护期天数写进系统，而不是写进口头约定 |
| ★★★☆☆ | 移动端可用 | 微信聊完能立刻在手机上补一条记录 |
| ★★☆☆☆ | 漏斗报表 | 5 人阶段只看「本周新增 / 在推 / 成单」三个数，别买 BI |
| ★☆☆☆☆ | 招聘网站 API 直连 | 加分项，多数要额外付费，不是必需 |

**明确不需要的**：多级审批流、组织架构、绩效模块、AI 面试。这些是甲方 HR 系统的卖点，猎头用不上，还会拖慢上手。

## 三、方案对比

| 方案 | 类型 | 5 人年费（实际成交区间） | 简历解析 | 上手成本 | 适配度 |
|---|---|---|---|---|---|

- 国内 SaaS 基本不公开报价，上表是按 **5 账号、年付、无定制、不私有化** 给的实际成交区间。谈的时候拿「年付 + 不做定制 + 不接私有化」换折扣，通常还能再压 10–15%。
- Moka 这类是给甲方 HR 设计的，流程围绕「职位审批—面试安排」，猎头最需要的「候选人多次推荐记录、客户维度成单统计」反而弱，不建议。

## 四、推荐方案：谷露 Gllue 猎头版

**为什么是它**：产品逻辑就是按「顾问—候选人—职位—客户—推荐记录」建的，不是把 HR 招聘系统改一改。5 人规模买基础版够用，不用上定制。

**5 人版必须落地的 6 个动作**：

1. **账号一人一号，不共享**。共享账号 = 归属记录失效 = 分成吵架。
2. **简历入口统一到邮箱**。把团队公共邮箱接进 ATS，微信收到的简历转发到该邮箱。这一步做完，80% 的录入工作量直接消失。
3. **查重规则**：手机号 + 邮箱双字段唯一，录入时强提示「该候选人已在 XX 名下，首录于 X 月 X 日」。
4. **归属规则写进系统**：首录者拥有，保护期 90 天（按实际成单周期调），超期未推进自动释放到公共池。这条比任何功能都重要。
5. **必填字段收窄到 5 个**：姓名、手机、当前公司/职位、来源渠道、下一步动作 + 日期。其余全部选填。字段越多，填的人越少。
6. **每日 10 分钟站会只看一个视图**：今天到期跟进 + 超过 7 天无动作的候选人。就一个视图，别做报表。

**预算明细**：

| 项目 | 金额（元） |
|---|---|
| 5 账号年费 | 12,000–20,000 |
| 简历解析 / 邮箱接入 | 通常含在套餐内，签约前书面确认 |
| 实施与培训 | 0（厂商标准远程培训） |
| **合计** | **≤ 20,000** |

**如果报价顶到 2 万**：优先砍「高级报表 / API 模块」，不要砍账号数。买 3 个账号 5 个人轮用，归属记录一定乱，省下的钱不够赔一次分成纠纷。

## 五、备选方案：飞书多维表格（预算敏感 / 先跑通流程）

**适用场景**：流程规则还没定死，想先花两周跑顺再决定要不要花钱；或者预算被压到 1 万以内。

**做法（2 人日可搭完）**，四张表用「关联」字段串起来：

1. **候选人表**：姓名、手机、邮箱、当前公司、当前职位、来源、归属顾问、状态、首录时间
2. **职位表**：客户、职位名、薪资范围、HC、对接人、状态
3. **推荐记录表（核心）**：关联候选人 + 关联职位 + 推荐日期 + 当前阶段（推荐 / 面试 / offer / 入职 / 淘汰）+ 淘汰原因
4. **跟进记录表**：关联候选人 + 跟进日期 + 方式（微信 / 电话 / 邮件）+ 摘要 + 下次跟进日

**必须配的 3 条自动化**：

- 新增候选人时按手机号查重，重复则私信录入人
- 跟进日期到期当天 09:00 推送提醒给归属顾问
- 推荐状态变为「入职」时通知全员（顺便当喜报）

**成本**：飞书免费版 50 人以内可用，多维表格有单表记录数上限（2 万条量级）。5 人团队一年新增候选人通常 1,000–3,000 条，够用两三年，超了再升商业版（5 人约 3,000 元/年）。

**代价**：简历解析靠多维表格的 AI 字段做文本提取，准确率不如专业 ATS，需要人工校对；没有行业标准的猎头漏斗视图，要自己拼仪表盘。**这是省钱的真实成本，不是「平替」。**

## 六、微信怎么办（绕不过去）

任何 ATS 都接不进个人微信，别信「打通微信」的宣传。可行做法是**把微信降级为通道，把 ATS 升级为唯一事实来源**：

1. **企业微信 + 客户联系**：客户沟通走企业微信，聊天记录可存档、可分配给离职同事接管。人走了客户不跟着走，这一条对 5 人团队价值极大。
2. **硬规则**：微信聊完 5 分钟内，手机端 ATS 补一条跟进记录，一句话即可（「客户要 3 年经验，已推 2 人」）。不补 = 不算跟进。
3. **周检视**：每周五抽查「本周有微信沟通但 ATS 无记录」的候选人。前两个月每周查，形成习惯后改每月查。
4. **简历统一走邮箱**：微信收的简历转发到 ATS 绑定邮箱自动解析，录入时间从 3 分钟压到 10 秒。

## 七、上线路线（14 天）

| 时间 | 动作 | 负责人 |
|---|---|---|
| D1–D2 | 定规则：归属、保护期、必填字段、阶段定义。写成一页纸，全员签字 | 业务负责人 |
| D3–D5 | 开通账号，导入历史数据 | 1 名顾问兼职 |
| D6 | 2 小时培训：只讲「怎么录一个人、怎么推一个职位、怎么看今天的待办」 | 全员 |
| D7–D13 | 双轨运行：新候选人只进 ATS，Excel 冻结为只读 | 全员 |
| D14 | 复盘：录入率、平均录入耗时、待办完成率。不达标先调字段，再考虑换工具 | 业务负责人 |

**历史数据迁移——不要全量导。** Excel 里 80% 是死数据，导进去只会让系统变脏。

- 只导「近 12 个月有过沟通」的候选人，通常几百条
- 先清洗：手机号去空格、去 +86、公司名统一简称、按手机号去重
- 用 ATS 的 Excel 模板批量导入，导完抽查 20 条
- 更早的数据留一个 Excel 归档包，需要时再查

| 项目 | 谷露方案 | 飞书方案 |

| 软件年费 | 12,000–20,000 元 | 0–3,000 元 |
| 搭建人力 | 0.5 人日 | 2 人日 |

## 九、风险与止损

| 风险 | 应对 |
|---|---|
| 买了不用，三个月退回 Excel | D14 设硬指标：候选人录入率 ≥ 90%，跟进记录日均 ≥ 5 条。不达标先减必填字段（多数是这个原因），再考虑换工具 |
| 顾问抵触「被监控」 | 明确 ATS 只用于协作和归属，不做考勤、不做通话时长统计。这条要当面讲清楚 |
| 归属规则引发争议 | 规则上线前全员确认，上线后 3 个月内不改。中途改规则比没有规则更伤 |
| 厂商涨价 / 停服 | 年付不签三年；导出功能必须可用，每月备份一次全量数据到本地 |
| 数据合规 | 简历属个人信息，一人一号、离职当天停用，批量导出需负责人审批 |

## 十、一句话执行建议

**先花 2 天把规则定死（归属、保护期、必填字段），再花 2 周把系统跑起来。工具选谷露，预算不够选飞书多维表格。真正决定成败的不是买哪个，是「微信聊完 5 分钟内必须回填」这一条能不能执行下去。**
