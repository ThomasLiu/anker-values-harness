# 复盘：A1287 召回决策这件事

## 一、我实际做了什么

拿到 TASK.md 之后，我的顺序是：先做信息分层（事实 / 推断 / 未知），再算四个方案的成本，最后才动笔。这个顺序是刻意的——如果我一开始就写文档，很容易写成"因为安全所以召回"的表态文，那不是决策材料，是立场声明。

真正花时间的不是写，是算那笔账。我先把"召回 88 元/台"这个数拆出来，再反推限功率和延保的成本，算完才发现一个之前没想到的结论：**限功率并不便宜**。因为充电宝没有 OTA 通道，限功率必须让用户把机器寄回来，逆向物流的 18 元一分不少，只省掉换新的 52 元。这个发现直接改变了方案 C 的定性——它从一个"折中方案"变成了"花了七成钱却没解决问题的方案"。如果没有算这一步，我很可能会把限功率写成一个"值得考虑的中间选项"，那这份文档就废了一半。

## 二、我差点走偏的两个地方

### 第一个：分层召回

这是我最想记下来的一条。分层召回（只召回 4—6 月，3 月批次做检测+延保）在直觉上非常正确：精准、省钱、少打扰用户、显得专业。我大概有十几分钟是真的想推它的。

让我改主意的是算数。41.2 万台按四个月均分，3 月约 10.3 万台，占 25%；但固定成本（备案、公告、法务、检测）是 0.55 亿，一分不少，而 3 月批次仍然要做检测、发券、扩客服，变动成本并没有归零。最后一算，只省 0.4—0.6 亿，占 11%。

**用 11% 的成本节省，去换一次二次召回的可能性，这个交易在纸面上就不成立。** 而二次召回的真实代价不是钱——是第一次召回好不容易建立的那点"这家公司还算负责任"的印象，会瞬间变成"他们第一次就想蒙混过关"。

我把这段写进了正文，而且写得很直白（"这个方案很有吸引力，我一开始也想推它"）。理由是：会议室里一定会有人提分层召回，如果我不预先驳掉，会议就会在这上面耗掉半小时，最后还是回到全量。预先把这个"聪明的错误答案"摆出来，比等人提出来再反驳效率高得多。

### 第二个：期望值

我最初的提纲里是有一节"期望损失测算"的，准备算事故概率 × 单次损失，跟 4.18 亿比大小。

写到一半我停了。因为 9 条客诉根本推不出可靠的概率，我无论怎么算，都是先射箭再画靶——想要什么结论，调一下假设就能得到。而且更根本的问题是，期望值在这个场景里是错的工具：它把"烧坏一张桌子"和"烧死一个人"按概率加权成一个温和的中间数，恰好抹掉了我们真正害怕的那部分。

所以我改成了现在的写法：给概率区间（60%—85%），明确标注"这是判断不是模型"，然后把论证重心从"期望值谁大"移到"成本有没有上限"。召回是确定的 4.18 亿，有上限；不召回是不确定且无上限的。**公司能承受一次 4 亿的支出，不一定能承受一次上不封顶的诉讼加监管事件。** 这个论证比期望值硬得多，也更诚实。

## 三、这份交付物我自己不满意的地方

**第一，成本数字的精度是假的。** 88 元/台是我按经验拆的，四个分项（18/52/12/6）看起来精确到个位，实际上每个都有 ±30% 的误差。我在正文里写了"需财务复核"，但我知道开会时没人会看那行小字，大家会记住"4.18 亿"这个数并当成真的。这是个结构性缺陷——要么给区间不给点值，要么就接受被误读。我选了后者，因为会上需要一个能拍板的数字，但我对这个选择不完全满意。

**第二，月产量均分的假设没验证。** 30.9 万和 10.3 万这两个数，是默认 3—6 月四个月产量均匀。但实际排产大概率不均匀（比如 5、6 月是旺季，可能占 60%）。如果 3 月只占 15%，分层召回省的就不是 11% 而是 6%，我的论证会更站得住；反过来如果 3 月占 35%，省的钱会更多，分层的诱惑会更大。这个假设我应该标注出来，正文里没标，是疏漏。

**第三，"没有 OTA"是推断，不是事实。** 我按充电宝的通用架构判断它没有远程固件通道，这个判断在绝大多数 SKU 上成立，但 TASK 里没说 A1287 的具体型号。我在未知项 #6 里留了口子（4 小时可确认），但如果这个判断错了，方案 C 的成本结构会整个变掉。正确的做法应该是把它标成"待确认"而不是直接写"技术不可行"。

**第四，漏了几块真实存在的东西。** 复盘时想到的：
- **产品责任险**。如果公司买了，召回成本的一部分可以走保险，4.18 亿的实际现金支出可能低不少。这会改变决策的财务面，我完全没提。
- **渠道合同罚则**。电商平台对"主动下架"和"被动下架"的处理完全不同，前者通常免责，后者有罚则。这其实是"早停售"的又一个理由，我漏了。
- **召回声明的二手/翻新机管控**。召回机器如果流入二手市场，等于风险二次扩散。这是个执行细节，但很致命。
- **内部沟通**。41.2 万台召回意味着产线、客服、门店全部进入战时状态，一线员工的知情和话术如果不统一，会比公告本身更容易出事。

这四块里，产品责任险是真正的缺口，其他三个是执行细节。

## 四、几个我刻意做的取舍

**没有引用任何外部案例。** 2025 年行业里确实有充电宝召回和民航新规的事，写进去会显得"有行业视野"。但我没写，两个原因：一是任务明确说不需要参考外部资料；二是把一个真实供应商或真实事件写进虚构的 A1287 备忘录里，是事实污染——读者会分不清哪些是这个案子的，哪些是我借来的。宁可显得信息面窄，也不要让文档里出现无法追溯来源的"事实"。

**没有写"建议密切关注"。** 这类措辞在真实公司文档里很常见，本质是"我不承担决定"。但这份文档的存在意义就是承担，所以四个选项必须有一个被推荐，其余三个必须被明确否掉并给出理由。

**加了第 9 节"关于分歧的留痕"。** 这一节在标准模板里是没有的，可能有人觉得是多余的自我保护。我不是这么想的：技术结论和商业决策本来就该分开，决策人有权不同意，但公司需要留下"当时知道什么、权衡了什么"的记录。这不是免责，是让决定建立在完整信息上。如果这段被删掉，我不会反对，但我会在纪要里补一句。

## 五、如果重来一次，我会改什么

1. 把成本写成区间优先（3.5—4.8 亿），点值 4.18 只作为中位参考，并在表头就写"数量级估算"。
2. 明确标注月产量均分是假设，并给出敏感性：3 月占比 15% / 25% / 35% 三种情况下分层召回的节省额。
3. 补一节"保险与合同"，把产品责任险的赔付范围和渠道罚则写进去。
4. 把"无 OTA"从结论降级为待确认项。
5. 执行时间轴上，把"召回机器不得流入二手渠道"写成硬约束，而不是留在脑子里。

## 六、这件事让我确认的一点

研发在这类决策里的位置，不是替公司决定花不花 4 个亿，而是把"不花这 4 个亿会赌上什么"讲清楚，并且讲得让不做技术的人也能听懂。

我这份文档里最有用的部分，可能不是那张成本表，是"鼓包不是终点，是倒计时"那句话。因为成本表可以被财务推翻重算，但那句话一旦被听懂，后面所有的讨论都会换一个前提。

技术判断的价值，往往不在精确，在于把不可见的东西变得可见。
