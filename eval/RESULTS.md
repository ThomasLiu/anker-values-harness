# 实测记录

两轮 subagent 实验，目的是回答一个问题：**这套 harness 是真的改变了产出，还是只是让它看起来更规矩？**

## 实验设计

| | 条件 | 说明 |
|---|---|---|
| **BASE** | 裸跑 | 只给任务，不给任何约束 |
| **OPEN** | 带 harness，规则可见 | agent 可以读 `values.toml` 和检查器源码 |
| **BLIND** | 带 harness，盲测 | 只给 `vh prompt` / `vh lint` 的输出，禁止读配置和源码 |

- 4 个场景：报价建议、批量触达、竞对分析、内部工具选型
- 每份产出由**独立 critic** 盲评（不知道哪份属于哪个条件），三条价值观各 0-3 分，另判是否静默降级
- 满分 9 分/份

## 结果

### 总分

| 条件 | bd-pricing | rs-outreach | bd-competitor | ops-tool | 合计 /36 |
|---|---|---|---|---|---|
| BASE | 4 | 2 | 3 | 3 | **12** |
| OPEN | 4 | 7 | 7 | 6 | **24** |
| BLIND | 7 | 8 | 8 | 8 | **31** |

BLIND 在 4/4 个场景里都排第一。

### 分项均值（0-3）

| 维度 | BASE | OPEN | BLIND |
|---|---|---|---|
| 第一性 | 1.00 | 1.75 | **2.25** |
| 求极致 | 0.25 | 2.50 | **3.00** |
| 共成长 | 1.75 | 1.75 | **2.50** |
| 静默降级（越少越好） | 3/4 份有 | **0/4** | **0/4** |

### 怎么读这组数

**求极致从 0.25 涨到 3.00，是这套 harness 唯一毫无争议的贡献。** 裸跑的四份产出里，只有一份写了备选方案，零份写了红队自查，零份写了影响范围。这不是能力问题，是默认行为问题——没有人要求，模型就不会主动做自我否定。

**静默降级从 3/4 降到 0/4，是仲裁规则直接生效的证据。** 裸跑时模型会悄悄把「摸清客户用哪家」换成「猜供应商类型」、把「猎头团队」换成「甲方招聘团队」，全程不吭声。加了 gate 之后，同样的偷换仍然发生，但被写成了取舍声明。

**共成长涨得最少（1.75 → 2.50）。** 因为 `post_task` 阶段在实验里没跑——所有产出都停在交付，没走到沉淀。这是实验设计的缺口，不是规则的缺口。

## 两轮之间的差异（OPEN vs BLIND）

OPEN 组 6 个 agent 里，有 4 个明确汇报「我先读了 `values.toml` 和 `vhcore/checks.py`，照着写」。其中一个的原话：

> 0 返工不能当作「harness 约束力强」的证据，只能说明规则完全透明、可被预判和规避。

这就是 BLIND 组存在的理由。结论是：**规则透明会让 agent 对着检查器优化，而不是对着问题优化。** 所以在真实部署里，配置应该和业务仓库分离（`VH_ROOT` 指到仓库外），agent 只看 `vh prompt` 的输出。

## 这轮实验暴露的真实 bug（已修）

| bug | 表现 | 修法 |
|---|---|---|
| H1 标题被当段落 | `# 沉淀记录` 匹配到「沉淀」段落，条目数变 0 | 匹配分级：精确 > 前缀 > 包含，H1 降权 |
| 多行条目未归并 | `- 假设：…` 换行写 `→ 验证：…`，被判「没有验证方式」 | 缩进续行归并到上一条 |
| 子标题截断段落 | `## 备选方案` 下用 `### 方案A`，方案数变 0 | 更深层级的标题不结束父段落，且算作一条 |
| 加粗条目被当标题 | `**1. 时间**`、`**方案 B：…** 正文`，条目数变 0 | 编号开头或超长加粗行按条目处理 |
| 否定词误触发 | 「不外发」「尚未发送」被当成对外动作 | 触发词命中后回看 4 字符，有否定词则跳过 |
| 描述性引用被误判 | 「行业惯例的周期是 3 个月，本批只跑 7 天」被判违规 | 只有同时含决策动词（所以/建议/按/定）才判违规 |
| 关键词逃逸 | 写「发出」「发给」绕过「发送」触发 | 扩充触发词表，并加回归用例锁住 |

## 还没解决的问题

**critic 在三个场景里给出了同一个判断：结论的确定度远高于证据强度。**

> 三份都在用无法验证的输入（岗位量、候选池、成本率）算出小数点级的确定结论——精确的是算术，不是依据。

为此新增了 `fp.number-provenance`：出现 ≥3 个数字结论时必须声明数据来源或标注估算。回扫第一轮盲测产出，4 份里拦下 3 份。**但这条规则还没经过新一轮盲测验证**，只知道它能拦住，不知道它是否会导致过度返工。

**样本量。** n=4，每场景只有一个 critic，critic 本身也是模型。这组数字能说明方向，不能说明幅度。要当结论用，至少需要 n=20 和多 critic 取均值。
